# A4 audit: security and configuration

Auditor A4, read-only except this file. Tree audited: `master` working tree at `1886ede` (the requested `64bcbfc` exists as an object but is not in `git log` of HEAD; the notes cite wave-5 fixes, so HEAD is the newer tree). No pytest was run. "Verified" means read in source or run as a repro. "Believed" means inferred and not exercised.

Overall: the credential and upstream-text discipline is unusually good (see Positive controls). The material risks are operational. The default compose stack ships an unauthenticated admin API that can register stdio servers, published on all host interfaces. The release job is ungated. The config surface has drifted from its docs.

### Positive controls (verified, no action)

- Credentials: `decision_api_key` has `repr=False` and is `_FILE`-capable with size, UTF-8 and printable checks (`settings.py:189-224`). `RemoteSystemOneModel` keeps the key name-mangled and out of `__repr__`. Errors are raised after the `except httpx` block so no exception carries the Bearer header. `trust_env=False` and `follow_redirects=False` are set. Response size is capped at 1 MiB and JSON depth at 20.
- Outbound URLs are validated at the point of use on every request (`remote_systemone.py:248`). AOAI also pins the hostname suffix. Link-local/metadata literals are refused in all encodings (`urlcheck.py`).
- Upstream text: `ConnectorError` messages are fixed strings. The manager logs `type(exc).__name__` only (`manager.py:472-477`). The AOAI error path does not read the body ("it can echo the prompt"). The entrypoint logs only the exception type for DB errors. `redact()` and `scrub_log()` cover log-forging (CR/LF) and are linear-time.
- Auth: Bearer is checked first with no silent downgrade (invalid means 401). Identity headers are ignored. Hash comparison is constant-time with no early exit. A key shared by two principals matches nobody. An agent key equal to the admin token is refused at bootstrap. An unset admin token with keys present gives 403 (fail closed).
- Body cap: the 1 MiB middleware is outermost and covers both declared and chunked bodies (`body_limit.py`).
- Static: a path-traversal and symlink-escape guard (`resolve()` plus `is_relative_to`), and reserved prefixes 404 as JSON.
- Git: https only, `protocol.allow=never`, hooks off, `followRedirects=false`, ref charset forbids a leading `-`, `--` before positional args, a scrubbed environment (`HOME=/nonexistent`), and curated errors.
- Workflows: all actions are pinned to full SHAs with version comments. `persist-credentials: false` on every checkout. Workflow-level `permissions: contents: read` in CI and `{}` in release, with `packages: write` only on the image jobs. `cancel-in-progress` is limited to PRs. The CI smoke job masks its ephemeral secrets before exporting them, and `ci-gate` checks each `needs` result explicitly (so skipped does not pass).
- Container: non-root uid 1000 with writability probes and chown; HEALTHCHECK hits `/healthz`; the db publishes no host port; `.dockerignore` excludes `.env*`, `.git`, `tests` and `docs`.

## 5. Config meta-test proposal

Goal: prevent the drift found in A4-009 and the undocumented variables in section 2. One pytest module, `tests/test_config_registry.py`, runs without a database and without network.

1. **Collect the code set.** Walk `src/**/*.py`, `scripts/*.sh`, `Dockerfile*`, `docker-compose*.yml` with `re.findall(r"MCPR_[A-Z0-9_]*[A-Z0-9]", text)`. Subtract an explicit allowlist `NON_ROUTER = {"MCPR_RUN_SLOW", "MCPR_AGENT_KEY", "MCPR_KEY", "MCPR_IMAGE", "MCPR_BASE_IMAGE", "MCPR_INFERENCE_IMAGE", "MCPR_TORCH_INDEX_URL", "MCPR_HOST_PORT"}` (compose and test knobs; each needs a comment). Drop the bare prefix `MCPR_AOAI_` (it appears in f-strings and messages).
2. **Build the registry from `settings.py` itself.** Parse `settings.py` with `ast`, collect string literals matching the regex, and also derive `<NAME>_FILE` for every secret passed to `_secret(...)`. Treat the result as the declared set. Include `MCPR_ADMIN_TOKEN` through an explicit `ENV_ONLY = {"MCPR_ADMIN_TOKEN", "MCPR_DB_WAIT_TRIES", "MCPR_PORT"}` constant that lives next to the registry (these are read outside `Settings`).
3. **Assertions (bidirectional):**
   - code set minus `NON_ROUTER` is a subset of the declared set (no stray `os.environ` read, no variable that exists only in a docstring or message);
   - every declared variable appears in `.env.example` (active or commented line) AND in at least one of `docs/deploy.md`, `docs/backends.md`, `docs/INSTALL.md`, `docs/skills.md`, `docs/analytics.md`;
   - every `MCPR_*` token in `.env.example` and in those docs (excluding `INTEGRATION_NOTES-*`, which are history) is in the declared set, so phantom names like `MCPR_MCP_ALLOWED_HOSTS` fail;
   - every `os.environ` / `os.getenv` call under `src/` is in an allowlist of file:function pairs (`settings.py::from_env`, `settings.py::AoaiSettings.from_env`, `api/app.py::create_app`, `skills/gitsource.py::_default_runner` for `PATH` only). Anything new must be added deliberately.
4. **Enum documentation check.** For enum-valued variables (`EMBEDDING_BACKEND`, `DECISION_BACKEND`, `DEVICE`, `OPERATING_MODE`, `LAYA_NOUL_MODE`), import `EMBEDDING_BACKENDS` / `DECISION_BACKENDS` / `MODE_CONCURRENCY` and assert that every value is mentioned and that every value written in the `.env.example` comment for that variable is in the real set. This catches `local` in `.env.example`.
5. **Parse-time validation table.** A parametrised test over a `{var: (good, [bad...])}` table runs `Settings.from_env()` under `monkeypatch.setenv`. Each bad value must raise `ValueError` whose message contains the variable name. The table must cover every numeric and enum variable, and a second assertion checks that the table keys equal the declared numeric/enum set, so a new variable cannot skip validation.
6. **Secret hygiene.** For each secret variable (`DECISION_API_KEY`, `AOAI_API_KEY`, `AGENT_KEYS`, `DATABASE_URL`, `ADMIN_TOKEN`): set a canary value, build the settings, and assert the canary is absent from `repr(settings)`, from `caplog` text after `create_app`, and from `str(exc)` of every failure path; assert a `_FILE` variant exists for each and wins over the plain one.
7. **Mutation checks to perform once when landing it:** delete a line from `.env.example`; add a fake `os.environ.get("MCPR_FOO")` in `src`; revert `repr=False`; each must turn the suite red.

Estimated size: about 120 lines of test code. It fails today on A4-004, A4-009, the six undocumented variables, the roughly 30 variables missing from `.env.example`, and the phantom `MCPR_MCP_ALLOWED_HOSTS` in the notes (excluded by rule 3 only because notes are history).
