## 4. Meta-test proposal: every handled method and meta-tool is exercised over the real streamable-http harness

Goal: adding a handler, meta-tool or notification fails CI until a real-transport test covers it, in both eras.

1. Derive the expected surface from the server, never from a hand list.
   - Methods: `{m for m in SPEC_METHODS if gw.server.get_request_handler(m)}` (public accessor, SDK `lowlevel/server.py:526`) plus built-ins `initialize` (H) / `server/discover` (M). `SPEC_METHODS` = the 14 names in the SDK constructor table (`lowlevel/server.py` `_spec_requests`); also compute the complement as the "must be -32601" set.
   - Meta-tools: `[t.name for t in gw._render([]) + _SKILL_TOOL_DEFS]` from a gateway built with `route_fn` AND `skills` (so the list tracks `_META_TOOL_DEF`, `_FEEDBACK_TOOL_DEF`, `_SKILL_TOOL_DEFS`).
   - Notifications: `{ToolsListChanged, PromptsListChanged, ResourcesListChanged}` (M) and the three `*ListChangedNotification` types (H), gated on `skills`.
2. One conformance module `tests/test_gateway_surface_e2e.py` with a single real server fixture on port 0 (fixes A2-015) and a table
   `SURFACE: dict[tuple[era, key], Callable[[client], Awaitable]]` where `key` is a method, `tools/call:<meta-tool>`, or `notify:<type>`. Rows run each era through the real client (`ClientSession.initialize()` for H, `.discover()` for M) and assert a SUCCESS result shape (and for the unsupported set, `MCPError.code == -32601`).
3. A recording ASGI wrapper around `world["app"]` (outermost, test-only) logs `(era, method, tool_name)` for every POST (parse JSON-RPC body; era = `mcp-protocol-version` header or presence of `mcp-session-id`) and notification types seen on the client side (`message_handler` / `listen`). It appends to a module-level `COVERED` set.
4. The meta-test (same module, executes the table itself so it is order-independent and works under xdist):
   ```python
   def test_surface_table_matches_server(world):
       expected = {(era, m) for era in ERAS for m in handled_methods(world["gw"])}
       expected |= {(era, f"tools/call:{t}") for era in ERAS for t in meta_tool_names(world["gw"])}
       assert expected <= set(SURFACE), f"uncovered: {sorted(expected - set(SURFACE))}"
       assert set(SURFACE) <= expected | UNSUPPORTED_ROWS, "stale row"
   @pytest.mark.parametrize("key", sorted(SURFACE))
   async def test_surface_row(served, key): ...  # runs row, then asserts key in COVERED
   ```
   The first test fails when a handler/tool is added without a row (and when a row refers to a removed one); the parametrized rows prove each key really crossed the HTTP wire (recording wrapper), not a unit-level shortcut. Also assert `UNSUPPORTED` rows return -32601 and that a subsequent `ping` still works (server not wedged).
5. Cheap extras in the same module: authenticated `ping` both eras; both-era `tools/call` of an unexposed-but-authorized tool after a re-route; two concurrent sessions of one agent both receive H `tools/list_changed` and a different agent's session does not; Host/Origin rejections (A2-012); 2 MiB POST -> 413 (A2-013); handler exception -> curated error (A2-001).
