## 2. The dialog failure: hypotheses (ranked)

Facts (verified):
- CI run 37893711025: node v20.20.2, npm 10.8.2, vitest 4.1.11 (ui/package.json:38), jsdom 26.1.0, react 18.3.1, @fluentui/react-components 9.74.9, tabster 8.8.1. Failure at PlaygroundPage.test.tsx:98 (`screen.findByRole("dialog", {}, {timeout:5000})`). The test is the 8th file test; earlier tests in the same file open Fluent dialogs/tooltips in the same jsdom window.
- Same signature reproduced locally on this box (load avg ~80, nproc 112, so natural contention): unmodified code failed 4/4 full-file runs at the same test (line 98), and failed a different dialog test ("admin-only activation..." at 1 of 4) - sometimes it passes. Run in isolation (`-t`), it passes. So it needs prior tests in the same file/window.
- With `DEBUG_PRINT_LIMIT=200000` on a failing run the DOM contains the dialog, and it is hidden from the accessibility tree: `<div role="dialog" aria-modal="true" aria-hidden="true" data-tabster='{"restorer":{"type":0},"modalizer":{"id":"modal-r16","isOthersAccessible":false,"isTrapped":true}}'>` plus a backdrop. RTL's default `hidden:false` excludes aria-hidden subtrees, so `findByRole("dialog")` can never match. (CI's dump is truncated at the 7000-char DEBUG_PRINT_LIMIT, which is why the CI log looked like "no dialog at all".)
- Where aria-hidden comes from (read in node_modules): DialogSurface sets `aria-hidden` only when `!unmountOnClose && !open` (react-dialog useDialogSurface.js), and Dialog defaults unmountOnClose=true (useDialog.js:18), so Fluent itself does NOT set it here. It is tabster's Modalizer: `ModalizerAPI.hiddenUpdate()` debounces 250ms (tabster/dist/esm/Modalizer.js:~434-441), then `_hiddenUpdate()` (Modalizer.js:~540-660) puts every modalizer whose userId != `activeId` into `hiddenElements` and calls `augmentAttribute(el,'aria-hidden','true')`. If the new dialog's modalizer is not yet the active one when that timer fires (activation happens only when focus lands inside it, `_onFocus` ~line 305; or `setActive`), the dialog's own surface is hidden. The sync un-hide path (`_onFocus`, ~line 316-322) only runs when focus enters it. The `_aug/_augMap/activeId` state lives on a window-scoped tabster singleton, so it leaks across tests in a file (RTL cleanup() unmounts but jsdom window and tabster instance persist).
- Mutation check (verified): scratch copy setup.ts adds `ModalizerAPI.prototype._hiddenUpdate = () => {}` (import from "tabster/dist/esm/Modalizer.js"): 4/4 full-file runs PASS under the same load, vs 4/4 FAIL unpatched at that time. Strongest evidence for H1.
- cleanup() IS run between tests (ui/src/test/setup.ts:13-20: afterEach cleanup + storage clear + restoreAllMocks). No matchMedia / ResizeObserver-motion mocking except a ResizeObserver stub (setup.ts:5-11). `useIsReducedMotion` (react-motion/lib/hooks/useIsReducedMotion.js:14) bails out when matchMedia is absent, so motion runs normally; presence motion (DialogSurface `presenceMotionSlot`, appear:unmountOnClose) uses Web Animations, which jsdom lacks, so Fluent falls back to instant mount. Not the cause (patching only tabster fixes it).

Discriminating experiment (already run): neutralise `ModalizerAPI.prototype._hiddenUpdate` in a scratch setup.ts, run the file 4x under load. Result 4/4 pass vs unpatched fail.
Why previous fixes failed: they targeted H2 (waiting for options/inputs) and the surface's "open transition". The surface is not mid-transition; it is hidden by tabster.

### Harness fix options (ranked, none applied; tracked files untouched)
1. (Recommended) In ui/src/test/setup.ts, stub tabster's modal-hiding: `import { ModalizerAPI } from "tabster/dist/esm/Modalizer.js"; (ModalizerAPI.prototype as any)._hiddenUpdate = () => {};`. Deterministic, removes a 250ms timer race, no production code touched. Caveat: private API (`_hiddenUpdate`) and tabster is a transitive dep (pinned 8.8.1 via lockfile); add a guard test that fails loudly if the method disappears (`expect(typeof ModalizerAPI.prototype._hiddenUpdate).toBe("function")`). Also verify the import resolves to the same module instance Fluent uses (it did: effect observed).
2. Test-level: query with `{hidden:true}` for dialog and its buttons (`findByRole("dialog",{hidden:true})`). Works but weakens the a11y assertion everywhere and must be repeated in every dialog test (SetupPage, other ConfirmDialog users). Only as a stopgap.
3. Reset between tests: after cleanup, `await new Promise(r=>setTimeout(r,300))` so the debounced timer drains. Adds ~300ms x tests (~3s/file); still racy under starvation. Not recommended.
4. `ConfirmDialog modalType="non-modal"` in tests only: changes the unit under test. Rejected.
5. Don't pursue: matchMedia reduced-motion mock (H4 rejected), blanket retries.
Add afterEach guard (verified useful to find leaks, in scratch): assert `document.querySelectorAll('[aria-hidden="true"]:not([data-tabster-dummy])').length===0` AFTER cleanup, so the leaking test names itself.
